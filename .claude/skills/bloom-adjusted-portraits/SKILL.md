# 似顏繪調整版作業（AI agent 版）

活動前，每位有作品的來賓都要有一張修好的「調整版」。來賓簽到時，系統會自動把調整版交給他；沒有作品的來賓只完成簽到。你的工作是幫工作人員把這件事**正確**做完：不傳錯人、不漏人、不亂花錢，也不提早開放簽到。

修圖本身由人完成。你負責的是修圖前後的流程：檢查、下載、配對、上傳和核對。

## 環境設定

所有腳本都在這個 skill 的 `scripts/` 資料夾，用 Node 20 以上直接執行，不需要安裝任何套件。

- `BLOOM_ADMIN_SECRET`：後台管理密碼，**必填**。請使用者自己在終端機設定（`export BLOOM_ADMIN_SECRET=…`）。不要要求使用者把密碼貼進對話，也不要把密碼寫進指令、檔案或任何輸出裡。
- `BLOOM_BASE_URL`：網站網址，選填，預設 `https://it-smart-bloom.vercel.app`（正式環境）。在本機測試時改成 `http://localhost:3059`。

**每次動手前，先說清楚目前連的是哪個網站。** 預設就是正式環境，裡面是真實來賓的資料。

## 安全規則（不可違反）

**一定要先取得人的確認，才能執行：**
- `upload.mjs --apply`：先跑預覽，把配對表給人看，等對方同意後，用預覽顯示的數字執行 `--apply --expect N`。
- `regenerate.mjs --apply`：會使用 OpenAI 額度，同樣先預覽、取得同意，再用 `--expect N` 執行。

**絕對不要做，只能請負責人在後台自己操作：**
- **開放簽到**：只有 `status.mjs` 判定「可以開放」之後，才建議負責人去後台切換，你不能自己開。
- **開放照片收件**：開放後來賓可以重傳照片，產生新作品，原本的調整版就作廢了。
- **按「允許重新上傳」**：原因同上。
- **還原原圖、資料重置、修改名單**：都不是這個流程的一部分。
- **自己撰寫 API 呼叫**：只能用腳本，不要繞過腳本裡的預覽和數量檢查。

`--expect` 是防呆機制，數字一定要來自**剛剛跑的那次預覽**。資料夾內容改變後，要重新預覽、重新取得確認，不能沿用舊的數字。

## 流程

照順序進行。每一步做完都回報結果，再進行下一步。

1. **檢查狀態**：`node scripts/status.mjs`
   這一步只讀取資料。回報有作品的人數、已調整幾位、未調整和生成失敗的名單、簽到和照片收件的狀態。照片收件如果還是「收件中」，請負責人先在後台的「現場總覽」關閉。

2. **生成失敗的人先處理**：`node scripts/regenerate.mjs`
   有兩種做法，請負責人選：
   - **重新生成**：先預覽名單，取得同意後執行 `--apply --expect N`。會使用 OpenAI 額度。要在下載原圖之前完成，否則這些人不會出現在下載的檔案裡。如果出現「額度不足」或「金鑰無效」，停下來交給負責人。
   - **不重新生成，直接上傳調整版補上**：由人另外做好這位來賓的圖，跟其他修好的圖一起上傳。上傳後就是他的作品，簽到時會交給他，不花額度。他沒有原圖可下載，檔名（含來賓編號）請從 `status.mjs` 或 `download.mjs` 的輸出照抄。

3. **下載原圖**：`node scripts/download.mjs --out <資料夾>`
   存下的數量要等於有作品的人數。檔名格式是 `座位_姓名_來賓編號.jpg`，最後一段的來賓編號是配對的依據。把資料夾交給修圖的人時，要提醒對方：**不要改檔名**；匯出成 JPEG、PNG 或 WebP，每張 40 MB 以內、約 1 億像素以下，不支援 HEIC 和 PSD。
   如果是要修第二輪，加上 `--current`，下載來賓目前會收到的版本（已含調整版）。

4. **預覽配對**：`node scripts/upload.mjs --dir <修好的資料夾>`
   把配對表和總結回報給人看，並特別點出：
   - 標示「依座位」或「依姓名」的列：檔名裡沒有來賓編號，請人逐一確認沒有配錯；
   - 「會取代現有調整版」的列：這次上傳會覆蓋先前的版本；
   - 「生成失敗，以這張補上作品」的列：這張會成為該來賓的作品，請人確認是本人；
   - 「沒有上傳照片，以這張建立作品」的列：來賓從沒交過照片，這張會成為他的作品；請人確認真的要給這位來賓，而不是檔名對錯人；
   - 每一個 ✗ 列，以及它的原因（對照下方的訊息表）。

   建議先拿 1–2 張試傳：把它們放進另一個資料夾，對那個資料夾預覽並上傳，然後請負責人在後台用「查看作品」確認。

5. **上傳**：取得同意後執行 `node scripts/upload.mjs --dir <資料夾> --apply --expect N`
   腳本一次傳 3 張。遇到網路、儲存空間、登入或簽名問題會整批停下；單一檔案的問題則會略過並繼續。結束後回報成功和失敗的清單。如果整批停下，先排除原因，然後把還沒上傳的檔案放到另一個資料夾，重新預覽、取得確認後再上傳。

6. **核對**：再跑一次 `node scripts/status.mjs`
   一直重複步驟 4–6，直到「未調整」為 0。等腳本判定「可以開放簽到」，再告訴負責人：可以到後台的「報到管理」把開關切到「報到開放中」。

## 回報時要讓人知道的事

- 活動當天，來賓要用**自己的手機**到 `/check-in` 簽到，才會收到作品。工作人員按「手動報到」只會記錄來賓已抵達，不會把作品給他。
- 開放簽到後如果又換了圖，已經簽到的來賓要**再簽到一次**才會看到新圖。他如果已經下載了舊圖，就沒辦法收回。
- 領取連結從簽到當下起 7 天內有效。

## 訊息與處理方式

| 訊息 | 原因 | 怎麼做 |
| --- | --- | --- |
| 對不到來賓 | 檔名沒有來賓編號，也不是座位或姓名 | 改回下載時的檔名，或改成座位（`L5.jpg`） |
| 這個座位有多位來賓／有多位來賓同名 | 用座位或姓名無法確定是誰 | 用含來賓編號的原始檔名 |
| 這位來賓的作品仍在生成中 | 作品還在生成 | 等它完成或失敗後再上傳 |
| 格式不支援 | HEIC、PSD、TIFF 等 | 匯出成 JPEG 或 PNG |
| 檔案必須小於 40 MB／圖片解析度過高 | 檔案太大，或超過約 1 億像素 | 縮小尺寸或另存為 JPEG |
| 多個檔案對到同一位來賓 | 同一人有兩張以上 | 只留一張 |
| 上傳的檔案不是有效的圖片／無法讀取這張圖片 | 檔案損毀，或副檔名和實際格式不符 | 重新匯出那張 |
| 無法上傳到儲存空間 | 網路中斷 | 恢復後重新預覽，再上傳剩下的檔案 |
| Unauthorized | 密碼錯誤或沒有設定 | 請使用者確認 `BLOOM_ADMIN_SECRET` |
| 此環境只能上傳 4 MB 以下的圖片 | 伺服器沒辦法產生上傳用的簽名網址 | 停下來，請負責人檢查 Vercel 上的服務帳號設定 |
| OpenAI 額度不足／OpenAI API 金鑰無效 | OpenAI 帳號的問題 | 停下來，請負責人儲值或更新金鑰 |

遇到表上沒有的訊息：停下來，把原始訊息轉給負責人，不要自己重試整批。

給工作人員看的完整手冊（以後台畫面操作為主）在 Claude Docs 的「似顏繪調整版作業手冊」。這個 skill 和那份手冊描述的是同一套流程。
